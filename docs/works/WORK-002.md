# WORK-002 — Sitesの公開経路・本人限定・保存機能を実証

状態: 未着手
担当案: Sites操作担当＋Codex
前提: WORK-001

## 目的

大量に画面を作る前に、ローカルソースから本人限定Siteへ反映できる経路を確認する。

## 成果物

- docs/sites/compatibility-report.md
- docs/sites/publish-runbook.md
- apps/site/の最小アプリ

## 変更範囲

- apps/site/
- docs/sites/
- scripts/site/

## 実施内容

- 架空データだけの最小Siteを公式スターター/互換構成で作る。先にフレームワークを決めつけない。
- apps/siteをローカルソースとして作成・バージョン保存できるか実機確認する。サブディレクトリ非対応なら同じリポジトリから許可リスト方式でSite配布物を作る。第二の正本を作らない。
- 元GitコミットとSiteの保存版/公開版の対応を記録する。GitHub pushを自動公開とみなさない。
- 実デプロイは本人操作として、個人利用側・共有相手なしを確認する。管理者権限のあるワークスペースを本人だけと呼ばない。
- 未ログイン/権限のない別アカウントで画面・API・ファイル経路を検査する。拒否は401/403またはログイン誘導等、実挙動で判定する。
- 合成の小ファイルとメタデータをD1/R2へ保存し、再訪後の読出しとコード更新後の保持を確認する。

## 完了条件

- 公開操作経路・対応するソースSHA・Site版が記録される。
- 本人以外に試験データが返らない。未検証のアクセス経路は未完了とする。
- 少量の試験ファイルが再訪後に同じハッシュで読める。
- 公開のためのソース/ビルドに原HTML・本番DB・Python学習データが入らない。
